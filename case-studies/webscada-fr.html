ÉTUDE DE CAS 04 · WEB TEMPS RÉEL · SCADA

WebSCADA Pro

Une plateforme de supervision industrielle temps réel : synoptiques SVG, alertes à 3 niveaux, tendances 24 heures et OEE — diffusées au navigateur par WebSocket en moins de 15 ms.

ReactNode.jsSocket.ioInfluxDB

SOMMAIRE

01Problème

Les opérateurs industriels vivent encore dans des SCADA de bureau hérités — lents à mettre à jour, difficiles à atteindre à distance, compliqués à intégrer aux autres systèmes métier. L'objectif : une interface de supervision nativement navigateur avec une télémétrie réellement temps réel.

02Contexte

  • Stack web moderne (front-end React, back-end Node).
  • Stockage de séries temporelles pour l'historique et les tendances (InfluxDB).
  • Exigence : gestion d'alarmes à trois niveaux de sévérité et d'une métrique de disponibilité (OEE).

03Architecture

CHEMIN DE DONNÉES

04Méthodologie

  • Chemin temps réel : télémétrie poussée via WebSocket vers React — pas de polling.
  • Chemin historique : requêtes temporelles vers InfluxDB pour les tendances 24 heures.
  • Alarmes : moteur à seuils avec 3 niveaux (info / avertissement / critique), persistées et acquittées.

05Implémentation

  • Composants synoptiques SVG rendus déclarativement dans React depuis un modèle d'équipements.
  • Serveur Socket.io diffusant les deltas d'état à tous les clients connectés.
  • OEE calculé depuis les fenêtres disponibilité / performance / qualité.

06Résultats

<15 mslatence de télémétrie temps réel
24 htendances persistantes
3 niveauxgestion des alarmes

Le chemin WebSocket garde une interface pratiquement vivante, et les synoptiques SVG donnent aux opérateurs une vue d'usine familière sans le runtime de bureau hérité.

07Enseignements

  • La synchronisation par deltas (envoyer les changements d'état, pas les images complètes) est ce qui maintient la faible latence à l'échelle.
  • Le SVG déclaratif depuis un modèle bat les écrans dessinés à la main — les changements d'équipement restent bon marché.
  • Les alarmes ont besoin d'un flux d'acquittement, pas seulement d'un affichage.

08Pistes d'amélioration

  • Alertes prédictives alimentées par les méthodes de détection d'anomalies utilisées dans le suivi OCP.
  • Ingestion native de protocoles PLC (Modbus / OPC-UA).
  • Tableaux de bord par rôle et journal d'audit pour les opérateurs.
