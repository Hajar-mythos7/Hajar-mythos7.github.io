ÉTUDE DE CAS 02 · PFA 2026 · IA EMBARQUÉE · VISION PAR ORDINATEUR

Caméra intelligente de détection d'intrusion

Une caméra de détection de personnes fonctionnant entièrement sur un Raspberry Pi 4 — YOLOv8n pour la perception, logique d'alerte à 3 niveaux et MQTT pour l'intégration.

Raspberry Pi 4YOLOv8nOpenCVMQTTGPIO

01Problème

Les caméras d'intrusion classiques basées sur le mouvement se noient dans les fausses alertes — n'importe quelle ombre en mouvement les déclenche. L'objectif : une caméra qui détecte spécifiquement les personnes, tourne sur une carte embarquée économique, et alerte avec trois niveaux de gravité au lieu d'un simple signal binaire.

02Contexte

Livré comme stage PFA 2026. Contraintes : un seul Raspberry Pi 4, caméra USB, pas de GPU, faible latence, et une intégration propre avec les écosystèmes d'appareils existants via MQTT.

  • Inférence 100 % embarquée — aucun aller-retour cloud.
  • Alerte à trois niveaux : détecter → confirmer → escalader.
  • Actionnement physique via GPIO (LED / buzzer).

03Architecture

PIPELINE (SUR L'APPAREIL)

04Méthodologie

  • Modèle : YOLOv8n — choisi pour une inférence efficace sur CPU sur le Pi 4.
  • Logique : seuils de confiance mappés à 3 niveaux d'alerte, débouncés dans le temps pour éviter le clignotement.
  • Sorties : GPIO (LED / buzzer) pour l'actionnement local + topic MQTT pour les tableaux de bord distants.

05Implémentation

  • Boucle de capture Python + OpenCV branchée sur le détecteur YOLOv8n.
  • Machine à états de cooldown et d'escalade pour les niveaux d'alerte.
  • Broker MQTT publiant les événements de détection avec niveau et horodatage.

06Résultats

3 niveauxescalade d'alerte sur l'appareil
Edgezéro dépendance cloud
MQTTintégration propre des appareils

La détection spécifique des personnes a éliminé le problème de fausses alertes des capteurs de mouvement classiques, et la logique à 3 niveaux donne aux opérateurs une escalade signifiante au lieu d'un simple « bip » binaire.

07Enseignements

  • Le choix du modèle est un compromis latence/précision — un YOLO nano est ce qui rend l'edge possible.
  • Les machines à états comptent plus que le modèle dans l'UX d'alerte : débounce, cooldown, escalade.
  • MQTT découple la caméra de ses consommateurs — un appareil, plusieurs tableaux de bord.

08Pistes d'amélioration

  • Files de messages et compensation de mouvement de caméra pour les sites multi-caméras.
  • Anonymisation respectueuse de la vie privée avant toute synchronisation hors appareil.
  • Quantification du modèle (INT8) pour pousser le nombre d'images par seconde encore plus haut.
